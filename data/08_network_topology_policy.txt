============================================================
ข้อกำหนดการออกแบบเครือข่าย (Network Topology Design Policy)
============================================================

1. วัตถุประสงค์
------------------------------------------------------------
เอกสารนี้กำหนดหลักการออกแบบการเชื่อมต่อระหว่าง Zone ในเครือข่าย
เพื่อควบคุมเส้นทางการสื่อสาร ลดความเสี่ยงด้านความปลอดภัย และทำให้
การตรวจสอบ/แก้ปัญหาเป็นไปอย่างเป็นระบบ

2. นิยามคำศัพท์
------------------------------------------------------------
  Zone          : กลุ่มเครือข่ายที่มีระดับความเชื่อถือ/หน้าที่เดียวกัน
                  เช่น Server Zone, User Zone, Management Zone, DMZ
  Static Zone   : Zone ที่มีการกำหนดค่าคงที่ (Static) และมีความสำคัญสูง
                  เช่น Zone ที่ใช้ IP แบบ Static / Zone แกนกลาง / Zone ที่
                  ต้องควบคุมการเข้าถึงเข้มงวดเป็นพิเศษ
  Gateway Zone  : Zone เดียวที่ได้รับอนุญาตให้เชื่อมต่อเข้ากับ Static Zone

3. ข้อกำหนดสำคัญ (Core Rule)
------------------------------------------------------------
  "ระบบอนุญาตให้มีเพียง zone เดียวที่ต่อเข้ากับ static zone
   นอกนั้นให้ต่อเข้าหากันเอง"

ตีความและนำไปใช้ดังนี้:
  3.1 มี Zone เพียง 1 Zone เท่านั้น (เรียกว่า Gateway Zone) ที่มีลิงก์
      เชื่อมตรงกับ Static Zone
  3.2 Zone อื่น ๆ ทั้งหมด ห้ามมีลิงก์ตรงเข้า Static Zone
  3.3 Zone อื่น ๆ เชื่อมต่อถึงกันเองได้ (Inter-zone) ตามนโยบายที่กำหนด
  3.4 หาก Zone อื่นต้องการสื่อสารกับ Static Zone ต้องผ่านทาง Gateway Zone
      เท่านั้น และอยู่ภายใต้ Firewall/ACL ที่ควบคุม

หมายเหตุการตีความ: ข้อความต้นฉบับอาจตีความได้มากกว่าหนึ่งแบบ
(เช่น "ต่อเข้าหากันเอง" อาจหมายถึง Mesh เต็มรูปแบบ หรือ Hub-and-spoke)
ควรยืนยันกับเจ้าของข้อกำหนดอีกครั้ง และปรับข้อ 3.3 ให้ตรงกับความตั้งใจจริง

4. แผนผังตัวอย่าง
------------------------------------------------------------

                      +-----------------+
                      |   STATIC ZONE   |
                      +--------+--------+
                               |
                      (ลิงก์เดียวเท่านั้น)
                               |
                      +--------+--------+
                      |  GATEWAY ZONE   |  <- Zone เดียวที่ต่อเข้า Static
                      +----+-------+----+
                           |       |
              +------------+       +------------+
              |                                 |
        +-----+-----+    <----------->    +-----+-----+
        |  ZONE A   |   (ต่อหากันเอง)    |  ZONE B   |
        +-----+-----+                     +-----+-----+
              |                                 |
              +----------+     +----------------+
                         |     |
                      +--+-----+--+
                      |  ZONE C   |
                      +-----------+

ห้าม: Zone A / B / C ลากสายหรือสร้าง routing ตรงเข้า Static Zone

5. หลักการออกแบบระดับเครือข่าย
------------------------------------------------------------
5.1 การแบ่ง Layer 2/3
  - 1 Zone ต่อ 1 VLAN (หรือชุด VLAN) และ 1 Subnet อย่างน้อย
  - Routing ระหว่าง Zone ทำที่ Layer 3 Switch หรือ Firewall เท่านั้น
  - ปิด VLAN 1 สำหรับ user traffic และตั้ง Native VLAN ที่ไม่ได้ใช้งาน

5.2 ตัวอย่างการจัดสรร IP
  Static Zone   : 10.10.0.0/24
  Gateway Zone  : 10.20.0.0/24
  Zone A (User) : 10.30.0.0/24
  Zone B (Server): 10.40.0.0/24
  Zone C (Mgmt) : 10.50.0.0/24

5.3 ความซ้ำซ้อน (Redundancy)
  - Gateway Zone ซึ่งเป็นจุดเดียวเข้า Static Zone ถือเป็น Single Point
    of Failure ควรทำ HA (เช่น VRRP/HSRP หรือ Firewall cluster)
    โดยยังถือเป็น "Zone เดียว" ในเชิงนโยบาย

6. ตัวอย่างการบังคับใช้ด้วย ACL (Cisco IOS)
------------------------------------------------------------
บล็อก Zone อื่นไม่ให้เข้า Static Zone โดยตรง ที่ Layer 3 Switch กลาง:

  ip access-list extended BLOCK-TO-STATIC
   remark Allow only Gateway Zone to reach Static Zone
   permit ip 10.20.0.0 0.0.0.255 10.10.0.0 0.0.0.255
   deny   ip 10.30.0.0 0.0.0.255 10.10.0.0 0.0.0.255 log
   deny   ip 10.40.0.0 0.0.0.255 10.10.0.0 0.0.0.255 log
   deny   ip 10.50.0.0 0.0.0.255 10.10.0.0 0.0.0.255 log
   permit ip any any

  interface vlan 30
   ip access-group BLOCK-TO-STATIC in
  interface vlan 40
   ip access-group BLOCK-TO-STATIC in
  interface vlan 50
   ip access-group BLOCK-TO-STATIC in

ตรวจสอบ:
  show access-lists BLOCK-TO-STATIC
  show ip interface vlan 30 | include access list

7. การตรวจสอบความสอดคล้อง (Compliance Check)
------------------------------------------------------------
  [ ] นับจำนวน Zone ที่มีลิงก์ตรงเข้า Static Zone = 1 เท่านั้น
  [ ] ตรวจ routing table ว่า Zone อื่นไม่มี route ตรงไป Static Zone
      show ip route 10.10.0.0
  [ ] ตรวจ CDP/LLDP neighbor ว่าไม่มีสายเชื่อมต่อนอกแผน
      show cdp neighbors ; show lldp neighbors
  [ ] ทดสอบด้วย traceroute จาก Zone อื่นไปยัง Static Zone
      ต้องผ่าน Gateway Zone ทุกครั้ง
  [ ] ทบทวน ACL/Firewall rule อย่างน้อยไตรมาสละครั้ง

8. กระบวนการขออนุมัติเปลี่ยนแปลง
------------------------------------------------------------
  1. ส่งคำขอพร้อมแผนผัง Topology ใหม่
  2. ตรวจสอบว่ายังสอดคล้องกับ Core Rule (ข้อ 3)
  3. ทดสอบใน Lab (เช่น EVE-NG) ก่อนใช้งานจริง
  4. สำรอง config ก่อนเปลี่ยน
  5. ดำเนินการในช่วง maintenance window
  6. อัปเดตเอกสารและบันทึกผลการเปลี่ยนแปลง

9. ข้อยกเว้น
------------------------------------------------------------
การเชื่อมต่อใด ๆ ที่ขัดกับ Core Rule ต้องได้รับอนุมัติเป็นลายลักษณ์อักษร
ระบุเหตุผล ระยะเวลา และมาตรการควบคุมความเสี่ยงทดแทน
